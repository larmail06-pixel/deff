# «На слух» — музыкальный квиз на GitHub Pages и Supabase Cloud

Инструкция без своего сервера: всё бесплатно, настраивается через браузер, займёт 40–60 минут.

- **Сайт** лежит на GitHub Pages и доступен по бесплатному адресу вида `https://ваш-логин.github.io/na-slukh/`.
- **База, вход по почте и аудио** — в Supabase Cloud на бесплатном тарифе.
- **Письма с кодом входа** уходят через ваш Gmail.

### Что в архиве

```
README.md                      эта инструкция
docs/                          сам сайт — его публикует GitHub Pages
  index.html                   страница игрока
  admin.html                   админ-панель
  js/config.js                 ← сюда впишете адрес и ключ Supabase
supabase/
  schema.sql                   таблицы, права доступа, серверные функции
  email-template.html          шаблон письма с кодом входа
.github/workflows/
  keep-alive.yml               не даёт бесплатному проекту Supabase «уснуть»
```

Папка `.github` в некоторых системах скрыта. Если её не видно — не страшно: на шаге 13 файл создаётся прямо на GitHub.

## Шаг 1. Пароль приложения Gmail

Supabase будет отправлять письма от имени вашего Gmail. Обычный пароль от почты для этого не подойдёт — нужен отдельный пароль приложения.

1. Откройте https://myaccount.google.com/security.
2. Включите **двухэтапную аутентификацию**, если она выключена. Без неё пароли приложений недоступны.
3. Откройте https://myaccount.google.com/apppasswords.
4. Введите название, например `quiz`, и нажмите **«Создать»**.
5. Скопируйте 16-значный пароль вида `abcd efgh ijkl mnop` и сохраните его. Google покажет пароль только один раз.

Удобно завести для квиза отдельный Gmail, например `nasluh.quiz@gmail.com`: личный адрес не будет виден игрокам в письмах.

Лимит бесплатного Gmail — около 500 писем в сутки. Квизу на 10 человек нужно 10–30 писем за игру.

## Шаг 2. Аккаунты

1. **GitHub.** Зарегистрируйтесь на https://github.com/signup, если аккаунта ещё нет.
   - Логин станет частью адреса сайта: `https://ЛОГИН.github.io/…`. Выбирайте короткий и понятный.
2. **Supabase.** Откройте https://supabase.com/dashboard и нажмите **«Continue with GitHub»**. Отдельный пароль не нужен.

## Шаг 3. Проект Supabase

1. В панели Supabase нажмите **«New project»**. Если попросят создать организацию, назовите её как угодно и выберите тариф **Free**.
2. Заполните поля:
   - **Project name:** `na-slukh`.
   - **Database password:** нажмите «Generate a password» и **сохраните пароль** — пригодится для резервных копий.
   - **Region:** ближайший к игрокам. Для Казахстана подойдёт **Central EU (Frankfurt)**.
3. Нажмите **«Create new project»** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 4. Адрес проекта и публичный ключ

Вам нужны два значения.

- **Project URL** — адрес вида `https://abcdefghijklmnop.supabase.co`.
  - Найти: кнопка **«Connect»** вверху панели проекта или **Project Settings → Data API**.
- **Publishable key** — ключ, начинающийся с `sb_publishable_`.
  - Найти: **Project Settings → API Keys**.
  - Если там только старые ключи, подойдёт ключ **anon / public**.

> ⚠️ **Secret key** (или **service_role**) никуда не копируйте. Он даёт полный доступ к базе в обход всех правил. На сайте нужен только публичный ключ — он и задуман как публичный.

Теперь впишите оба значения в сайт.

1. Распакуйте архив на компьютере.
2. Откройте `docs/js/config.js` в Блокноте (Windows) или TextEdit (Mac, в режиме простого текста).
3. Замените две строки:

```js
  SUPABASE_URL: 'https://abcdefghijklmnop.supabase.co',
  SUPABASE_KEY: 'sb_publishable_XXXXXXXXXXXXXXXXXXXXXX',
```

Кавычки и запятые в конце строк не удаляйте. Сохраните файл.

## Шаг 5. Таблицы в базе

1. В меню слева откройте **SQL Editor** и нажмите **«New query»** (или «+»).
2. Откройте `supabase/schema.sql` в текстовом редакторе, выделите всё (Ctrl+A), скопируйте и вставьте в окно запроса.
3. Нажмите **«Run»** или Ctrl+Enter.
4. Если Supabase предупредит об «опасной операции» (в скрипте есть `drop policy if exists`), подтвердите запуск. Это безопасно: скрипт ничего не удаляет, если запускать его первый раз, и не трогает данные при повторном запуске.
5. Должно появиться **«Success. No rows returned»**.

Проверка: в меню **Table Editor** появились таблицы `profiles`, `questions`, `answers` и другие. В меню **Storage** появился бакет `fragments`.

## Шаг 6. Отправка писем через Gmail

Встроенная почта Supabase отправляет письма только участникам вашей команды в Supabase и не больше пары писем в час. Поэтому подключаем Gmail.

1. Откройте **Authentication → Emails**, вкладка **SMTP Settings**.
2. Включите **Enable Custom SMTP**.
3. Заполните поля:

| Поле | Значение |
|---|---|
| Sender email | ваш Gmail, например `nasluh.quiz@gmail.com` |
| Sender name | `На слух` |
| Host | `smtp.gmail.com` |
| Port number | `465` |
| Minimum interval between emails | `60` (секунд) |
| Username | тот же Gmail полностью |
| Password | пароль приложения из шага 1, **без пробелов**: `abcdefghijklmnop` |

4. Нажмите **«Save changes»**.

**Лимит писем.** После включения своего SMTP Supabase ставит лимит 30 писем в час. Для 10 игроков этого достаточно. Если нужно больше, откройте **Authentication → Rate Limits** и поднимите «Rate limit for sending emails», например до 100.

## Шаг 7. Шаблоны писем с кодом

По умолчанию Supabase присылает только ссылку. Наш шаблон добавляет в письмо ещё и **код**: это удобно, когда почта открыта на телефоне, а квиз — на компьютере.

Supabase использует два разных письма: одно для первого входа нового игрока, другое для всех следующих. Поэтому шаблон вставляется дважды.

1. Откройте **Authentication → Emails**, вкладка **Templates**.
2. Выберите шаблон **«Confirm sign up»**:
   - **Subject:** `Код для входа в квиз «На слух»`;
   - **Body:** удалите всё и вставьте содержимое файла `supabase/email-template.html` (в режиме редактирования HTML/Source);
   - нажмите **«Save»**.
3. То же самое сделайте для шаблона **«Magic link»**.

Шаблоны редактируются только при включённом своём SMTP, поэтому шаг 6 должен быть выполнен раньше.

## Шаг 8. Репозиторий на GitHub

1. На https://github.com нажмите **«+»** в правом верхнем углу → **«New repository»**.
2. Заполните:
   - **Repository name:** `na-slukh` — это имя станет частью адреса сайта;
   - видимость **Public** — бесплатный GitHub Pages работает только для публичных репозиториев;
   - галочку «Add a README file» **не ставьте**.
3. Нажмите **«Create repository»**.
4. На открывшейся странице нажмите ссылку **«uploading an existing file»**.
5. Перетащите в окно браузера **содержимое** распакованной папки: папки `docs`, `supabase` и файл `README.md`. Структура папок сохранится.
6. Дождитесь, пока файлы загрузятся, и нажмите **«Commit changes»** внизу.

Проверьте, что в репозитории есть `docs/index.html` и в `docs/js/config.js` стоят ваши значения, а не `YOUR-…`. Если забыли вписать: откройте файл на GitHub, нажмите ✏️ (Edit), исправьте и нажмите **«Commit changes»**.

**Публичный репозиторий — это безопасно.** В коде нет секретов: публичный ключ и так виден любому посетителю сайта. Правильные ответы и почты игроков хранятся в Supabase и закрыты правилами доступа.

## Шаг 9. Включите GitHub Pages

1. В репозитории откройте **Settings** (вкладка вверху) → **Pages** (меню слева).
2. В разделе **Build and deployment** выберите:
   - **Source:** «Deploy from a branch»;
   - **Branch:** `main`, папка **`/docs`**.
3. Нажмите **«Save»**.
4. Подождите 1–3 минуты и обновите страницу. Вверху появится **«Your site is live at https://ЛОГИН.github.io/na-slukh/»**.
5. Убедитесь, что включена галочка **«Enforce HTTPS»**. Для адресов github.io она обычно включена сразу.

Откройте адрес — должна появиться страница квиза с формой входа.

## Шаг 10. Сообщите Supabase адрес сайта

Без этого ссылка из письма вернёт игрока не на ваш сайт.

1. В Supabase откройте **Authentication → URL Configuration**.
2. **Site URL:** `https://ЛОГИН.github.io/na-slukh/`
3. В **Redirect URLs** нажмите **«Add URL»** и добавьте `https://ЛОГИН.github.io/na-slukh/**`. Две звёздочки в конце обязательны: они разрешают и главную страницу, и админ-панель.
4. Нажмите **«Save»**.

## Шаг 11. Первый вход и права администратора

1. Откройте `https://ЛОГИН.github.io/na-slukh/admin.html`.
2. Введите свою почту и нажмите **«Получить код»**.
3. Введите код из письма или нажмите ссылку в письме.
4. Страница сообщит, что прав администратора пока нет, и покажет готовую SQL-команду.
5. Скопируйте команду, выполните её в Supabase → **SQL Editor** и обновите страницу. Команда выглядит так:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'yourname@gmail.com'
on conflict do nothing;
```

Появятся вкладки **«Вопросы»** и **«Статистика»**.

## Шаг 12. Первый фрагмент и проверка

1. Вкладка **«Вопросы»** → **«Добавить фрагмент»**.
2. Выберите аудиофайл: MP3, WAV, M4A, OGG — всё, что открывает браузер.
3. Ползунком выберите начало отрывка и укажите длину от 3 до 60 секунд. Нажмите **«Прослушать отрывок»**, чтобы проверить.
4. Впишите 2–6 вариантов ответа и отметьте правильный.
5. Нажмите **«Сохранить фрагмент»**. Браузер сам вырежет отрывок и закодирует его в MP3 — на сервер уходит только он.

Затем проверьте всё глазами игрока, **лучше с телефона**:
1. Откройте `https://ЛОГИН.github.io/na-slukh/` и войдите с другой почтой.
2. Придумайте имя, нажмите на пластинку и ответьте.
3. Загляните в **«Рейтинг»**.

Если всё работает — отправляйте ссылку игрокам.

## Шаг 13. Чтобы проект не «засыпал»

Бесплатный проект Supabase ставится на паузу, если к нему неделю никто не обращался. Тогда сайт перестаёт работать, пока вы не нажмёте **«Restore project»** в панели Supabase. Данные при этом сохраняются.

Автоматическая «побудка» через GitHub Actions — раз в 3 дня:

1. В репозитории нажмите **«Add file» → «Create new file»**.
2. В поле имени введите ровно: `.github/workflows/keep-alive.yml`. Слэши сами создадут папки.
3. Вставьте содержимое файла `.github/workflows/keep-alive.yml` из архива и нажмите **«Commit changes»**.
4. Откройте вкладку **Actions**. Если GitHub попросит разрешить workflows, подтвердите.
5. Слева выберите **«Keep Supabase awake»** → **«Run workflow»**, чтобы проверить. Через полминуты должна появиться зелёная галочка.

GitHub отключает такие расписания, если в репозитории 60 дней не было никаких изменений, и присылает об этом письмо. Включить обратно можно кнопкой «Enable workflow» на вкладке Actions. Если проект всё же уснул — **«Restore project»** в панели Supabase, данные на месте.

## Шаг 14. Сохранность данных

На бесплатном тарифе Supabase не даёт скачивать резервные копии. Для квиза достаточно трёх простых привычек:
- **Исходные аудиофайлы** храните у себя: из них всегда можно заново нарезать фрагменты.
- **После каждой игры** выгружайте результаты: **«Статистика» → «Скачать CSV»**.
- **Вопросы и варианты** время от времени выгружайте: Supabase → **Table Editor** → таблица `questions` → **Export → CSV**.

## Как обновлять сайт

- **Поменять название квиза:** на GitHub откройте `docs/js/config.js` → ✏️ → исправьте `SITE_NAME` → «Commit changes».
- **Заменить файлы новой версией:** «Add file» → «Upload files», перетащите файлы с теми же именами в нужную папку и нажмите «Commit changes». Свой `config.js` при этом не перезаписывайте.

GitHub Pages опубликует изменения за 1–2 минуты. Браузеры могут держать старую версию в кэше до 10 минут, поэтому для проверки обновляйте страницу с Ctrl+F5.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| Сайт показывает 404 | Pages ещё публикуется — подождите пару минут. Проверьте, что в Settings → Pages выбрана папка `/docs`, а в репозитории есть `docs/index.html`. |
| «Сайт ещё не настроен» | В `docs/js/config.js` остались `YOUR-…`. Впишите адрес и ключ (шаг 4). |
| «Нет связи с сервером» | Проект Supabase на паузе → «Restore project». Или опечатка в `SUPABASE_URL`: адрес должен начинаться с `https://` и заканчиваться на `.supabase.co`, без слэша в конце. |
| Письмо не приходит | Проверьте «Спам». Затем Supabase → **Logs** → Auth: ошибка `535` или `Username and Password not accepted` значит неверный пароль приложения (шаг 1) или он вставлен с пробелами. |
| Ошибка «Email address not authorized» | Не включён свой SMTP — шаг 6. |
| «Слишком много попыток» | Повторное письмо на тот же адрес можно запросить через минуту. Общий лимит в час — в Authentication → Rate Limits. |
| Ссылка из письма ведёт на `localhost:3000` или на чужой адрес | Не заполнены Site URL и Redirect URLs — шаг 10. |
| Ссылка «устарела» | Ссылка и код одноразовые. Запросите новое письмо. На другом устройстве вводите код, а не переходите по ссылке. |
| В письме только ссылка, без кода | Шаблон вставлен только в одно из двух писем — шаг 7, оба шаблона. |
| «Нет прав администратора» | Выполните SQL из шага 11 с той почтой, под которой вошли. |
| Фрагмент не сохраняется | Запись в хранилище разрешена только администраторам. Проверьте, что в Storage есть бакет `fragments` (шаг 5), и что вы вошли как администратор. |

## Ограничения бесплатного варианта

- **Пауза после недели простоя** — решается шагом 13.
- **Лимиты Supabase Free:** база 500 МБ, файлы 1 ГБ, до 50 000 активных пользователей в месяц.
  - 15-секундный фрагмент весит около 240 КБ, так что в 1 ГБ поместится больше 4 000 фрагментов.
  - Одна игра на 10 человек по 20 фрагментов — около 50 МБ трафика, это немного даже при лимите бесплатного тарифа 5 ГБ в месяц.
- **Адрес сайта** — `ЛОГИН.github.io/na-slukh`.
  - Если назвать репозиторий `ЛОГИН.github.io`, сайт откроется просто по `https://ЛОГИН.github.io/`. Тогда на шаге 10 укажите этот адрес.
  - Позже можно подключить свой домен: Settings → Pages → Custom domain. Не забудьте обновить адреса в шаге 10.
- **Репозиторий публичный:** код сайта виден всем. Секретов в нём нет, а ответы и почты защищены на стороне Supabase.
